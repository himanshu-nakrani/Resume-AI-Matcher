# UI/UX overhaul: indigo-violet design system, grouped navigation, and page polish

A comprehensive visual upgrade across the resume-matcher frontend. The change replaces the muted gray-blue palette with a vibrant indigo-violet primary (`245 82% 67%`), introduces a full gradient utility system (hero, surface, primary), restructures sidebar navigation into labeled groups with active accent indicators, adds page transitions via Framer Motion, and polishes the home page hero, board columns, stats cards, score circles, and 404 page with gradient treatments and micro-animations. The approach is purely presentational — no business logic, routing, or data-fetching changes.

**Watch for:** The `PageTransition` component remounts children on every route change, which will reset local component state and trigger re-fetches for any queries that depend on mount lifecycle (confirmed). The `ScoreCircle` count-up animation fires only once per component instance due to a `useRef` guard but will replay on every route navigation because `PageTransition` remounts the page (confirmed). The font switch from DM Sans to Inter in `index.html` is incomplete — the CSS `--app-font-sans` references Inter, but no DM Sans fallback remains, meaning any content relying on DM Sans optical sizing will silently shift (confirmed).

## High-level view

The design system lives entirely in CSS custom properties and Tailwind's `@theme inline` block. Light and dark modes each get a full token set with the same HSL structure, keeping them in sync without runtime logic. One tension: components use three different mechanisms to express "brand gradient" — CSS variables, utility classes, and inline Tailwind color stops — which can drift from each other over time.

Navigation moves from a flat list to three labeled groups (Core, Insights, Jobs) with a separate, reduced `mobileNavItems` array for the bottom nav. The grouped structure improves scannability but introduces a discoverability gap on mobile where 6 of the 11 nav items are unreachable without a mechanism to access them.

Page transitions wrap all routed content in `AnimatePresence` with `mode="wait"`, meaning the exiting page must complete its exit animation before the entering page mounts. This adds 200ms of perceived latency to every navigation and forces full remounts of page components.

The score circle gains a count-up animation and colored glow, but the glow renders at 20% opacity even when `score` is 0, producing a misleading red halo around empty states.

## Mobile navigation gap

The sidebar groups 11 items into three sections, but the mobile bottom nav only surfaces 5 (Optimize, Tracker, Profile, History, Stats). The remaining 6 — Compare, Skills, Brand, Versions, Saved Jobs, Alerts — have no mobile navigation path. There's no hamburger menu, drawer, or "more" tab. On mobile viewports (`md:hidden`), users can only reach these pages via the command palette (`Cmd+K`), which isn't discoverable for most users.

```tsx
const mobileNavItems: NavItem[] = [
  { href: "/", label: "Optimize", icon: PlusCircle },
  { href: "/tracker", label: "Tracker", icon: LayoutGrid },
  { href: "/user", label: "Profile", icon: UserRound },
  { href: "/history", label: "History", icon: History },
  { href: "/stats", label: "Stats", icon: BarChart2 },
];
```

A common pattern is replacing the last bottom-nav slot with a "More" icon that opens a sheet listing the remaining items.

## PageTransition remount semantics

`PageTransition` uses `key={location}` with `mode="wait"`:

```tsx
<AnimatePresence mode="wait">
  <motion.div key={location} ...>
    {children}
  </motion.div>
</AnimatePresence>
```

When the key changes, React unmounts the previous subtree and mounts a new one. Every page component goes through a full mount cycle on navigation — `useEffect` hooks fire again, `useRef` values reset, and local `useState` is lost. For pages that fetch data via TanStack Query, this triggers a refetch unless the query is cached. The 200ms exit delay before the new page mounts is perceptible on fast navigations.

The interaction with `ScoreCircle` is the most visible side-effect: the `hasAnimated` ref resets on remount, so the count-up fires every time a user navigates back to the home page or any page displaying scores.

## Inline keyframe in not-found.tsx

The 404 page injects a `<style>` element inside the component body:

```tsx
<style>{`
  @keyframes float {
    0%, 100% { transform: translateY(0px); }
    50% { transform: translateY(-10px); }
  }
`}</style>
```

This creates a new `<style>` element on every render. It's inconsistent with the rest of the codebase which defines keyframes in `index.css` (`gradient-shift`, `shimmer`, `bounce-in`, etc.). Moving `float` to the CSS file would centralize the animation system.

## ScoreCircle glow at zero score

The glow color computation doesn't gate on `score > 0`:

```tsx
const glowColor = score >= 80
  ? "hsl(142 71% 45% / 0.3)"
  : score >= 60
    ? "hsl(38 92% 50% / 0.3)"
    : "hsl(0 65% 51% / 0.3)";  // fires for score === 0 too
```

A score of 0 (loading state, placeholder) gets a faint red glow — semantically misleading since a zero score isn't a "bad" score, it's the absence of a score.

## Gradient expression inconsistency

Three mechanisms coexist for "apply the brand gradient":

1. CSS custom properties: `var(--gradient-primary)` — defined as `hsl(245, 82%, 67%)` to `hsl(280, 80%, 60%)`
2. Utility classes: `.text-gradient-primary`, `.gradient-text`
3. Inline Tailwind: `bg-gradient-to-r from-indigo-500 via-purple-500 to-pink-500`

The button's gradient variant uses approach 3, hardcoding `indigo-500`, `purple-500`, `pink-500` which are Tailwind defaults (not the custom `245 82% 67%` primary). If the primary palette shifts, button gradients won't follow because they bypass the CSS variable system. The sidebar logo also uses hardcoded `from-indigo-500 to-purple-600`. These will drift from `--gradient-primary` on any future palette change.
